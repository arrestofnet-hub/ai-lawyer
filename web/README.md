# AI Lawyer Kazakhstan — независимый веб-чат (пилот v0.1)

Статус: независимый пилот опубликован на ailawyer.kz/chat и проходит пользовательское тестирование. Плагин в корне репозитория остаётся без изменений. Юридическая стратегия находится отдельно в strategy/LEGAL_ENGINE_V1.md.

## Что есть в этой версии
- Логин/регистрация исключительно с секретным кодом приглашения.
- Изолированные пользовательские дела, постоянная история переписки, карточка дела.
- Зашифрованное на диске хранилище AES-256-GCM для карточек, сообщений и прикреплённых файлов. Ключ хранить отдельно от резервных копий.
- Загрузка PDF, DOCX, PNG, JPG, WEBP, TXT, MD, CSV, до 7 МБ на файл, до 30 на дело, до 3 в одном запросе. Файлы отправляются в OpenAI Responses API только по выбору пользователя.
- Режимы консультации, противоречий, стратегии, документа, независимой перепроверки; вторичная модель для strategy/review.
- Поиск свежих правовых публикаций через OpenAI web_search, по возможности ограниченный официальными доменами РК. Поиск НЕ гарантирует применимость редакции нормы и не заменяет юридическую проверку.
- Ручная компактная юридическая память по делу на основе сохранённой переписки с явным сохранением противоречий.
- API-ключ хранится только на сервере, не отдаётся в HTML/JS. Секреты не попадут в GitHub.
- Суточный лимит запросов на пользователя, invite-only доступ и базовый rate limit.
- Отображение Markdown-ответов с заголовками, выделением, списками и таблицами (без вывода разметки в тексте).\n- Копирование очищенного текста, сохранение TXT, скачивание редактируемого Word (.docx) и PDF; экспорт доступен только владельцу дела.\n- Для Word: Times New Roman 14; для PDF: доступный серверный кириллический шрифт (Times, Liberation Serif или DejaVu Serif).\n- Код приглашения нужен только для первоначальной регистрации. Повторный вход — по электронной почте и паролю; сессия действительна семь дней.

## Запуск локально для закрытого теста
1. Установить Node.js >=20.
2. Задать переменные окружения из .env.example через системное окружение (не использовать dotenv без установки).
3. Генерировать DATA_KEY командой openssl rand -hex 32, хранить в менеджере секретов, делать зашифрованные резервные копии DATA_DIR.
4. В каталоге web выполнить npm run check, npm test, node server.mjs.
5. Открыть http://localhost:8791/chat/ . На localhost PUBLIC_ORIGIN должен быть http://localhost:8791.
6. Для регистрации нужен SIGNUP_INVITE_CODE. У пользователей без приглашения регистрации нет.

## Размещение на существующем VPS
Предполагается один отдельный systemd-процесс Node на 127.0.0.1:8791 с DATA_DIR на постоянном диске, права 0700. Существующий MCP на порту 8787 не трогать.

Nginx HTTPS-конфигурация ВНУТРИ действующего server блока (предварительно сохранить конфиг и проверить nginx -t):

    location /chat/ {
        proxy_pass http://127.0.0.1:8791;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 8m;
        proxy_read_timeout 135s;
    }

PUBLIC_ORIGIN должен точно соответствовать https://ailawyer.kz. Секреты в systemd EnvironmentFile с правами 0600, никогда не передавать их в чат или публичный GitHub. Требуется отдельная инструкция для установки на VPS и тестирования TLS, прокси, резервного копирования. На Railway для отдельной тестовой службы HOST=0.0.0.0, обязательно постоянный том DATA_DIR.

## Известные ограничения и условия публичного запуска
- Здесь только первая инженерная версия, НЕ полностью автономный юридический эксперт. Актуальность нормы и применимость судебной практики требуют второго проверяемого слоя с источниками и версионированием.
- Пока нет полноценного парсера/реестра доказательств по страницам, дедлайнового движка и биллинга. Выгрузка Word/PDF реализована для ответов модели, но не заменяет правовую экспертизу и специальное форматирование каждого типа процессуального документа.
- Полная переписка хранится, но в модель передаётся ограниченное окно + ручная сжатая карточка; компактирование запускать после существенных изменений дела.
- Локальный encrypted JSON store подходит для небольшого пилота на ОДНОМ процессе, не для масштабной многопользовательской системы. До открытого запуска мигрировать в PostgreSQL с RLS/изоляцией пользователей, транзакциями, аудитом и резервными копиями.
- Необходимо проверить правовое основание обработки персональных данных РК, информированное согласие на внешнюю обработку моделью, политику хранения/удаления и требования локализации данных.
- Реальные документы направляются в OpenAI API только по действию пользователя; удаление из локального дела не означает удаления из любого внешнего провайдера.
- Не использовать исходные чаты разработчика и документы клиентов как публичные образцы без удаления идентификаторов и законного основания.
- Нужны тесты с обезличенными казахстанскими кейсами, измерение ошибок и проверка реальными юристами.
- Ещё не реализованы восстановление пароля, блокировка массовых атак на нескольких IP, полноценные лимиты расходов по токенам, observability без ПДн, аудит действий и шифрованное резервное копирование.
- Без OPENAI_API_KEY чат не выдаёт ответы (503). Plus/Pro аккаунт ChatGPT не заменяет отдельную оплату API.

## API
GET /chat/health — проверка процесса; GET /chat/api/session — статус авторизации; POST /chat/api/auth/register|login|logout; GET/POST /chat/api/cases; GET/PATCH/DELETE /chat/api/cases/:id; POST /chat/api/cases/:id/documents с сырым содержимым файла и заголовком X-Filename, DELETE /chat/api/cases/:id/documents/:docId; POST /chat/api/cases/:id/chat; POST /chat/api/cases/:id/compact; GET /chat/api/cases/:id/export/:messageId?format=pdf|docx (только собственный сохранённый ответ AI).

## Регистрация, сохранение входа и Google OAuth (новая версия)

- **Email + пароль:** существующий вход и приглашённые аккаунты сохраняются без миграции, история дел остаётся привязанной к точному адресу email.
- **Флажок «Запомнить меня»:** при включении выдаётся HttpOnly/Secure/SameSite=Lax cookie до 30 дней; при выключении — браузерная session-cookie и не более 24 часов серверного срока. Нажатие «Выйти» отзывает серверную сессию в любом режиме.
- **Пароль:** хранится сервером только как salted scrypt hash. Не сохраняется приложением в localStorage, cookies или открытом тексте. Поля имеют стандартизированные атрибуты autocomplete; браузер сам предлагает сохранить пароль в своём менеджере.
- **Открытая регистрация по email:** активируется ТОЛЬКО при заданных SMTP_HOST, SMTP_USER, SMTP_PASS, SMTP_FROM. Первый шаг отправляет шестизначный код на почту, второй проверяет код (15 минут / максимум 5 попыток) и лишь после этого создаёт аккаунт. Без SMTP прежний invite-only механизм остаётся работать; не принимать клиентов в обход подтверждения почты.
- **Вход Google:** настроенный OAuth Web Client ID и secret в серверном EnvironmentFile включает кнопку. Используются Authorization Code + PKCE, подписанный state-cookie, nonce, серверная проверка JWT по Google JWKS, сопоставление по стабильному Google sub. OAuth-секрет Google и пользовательские токены не выдаются фронтенду.
- **Привязка Google к уже существующему email-аккаунту:** сначала войти по своему паролю, затем нажать «Подключить Google» и выбрать Google-аккаунт с тем же подтверждённым адресом. Автоматически объединять аккаунты только по совпадающему email запрещено.
- **Новые Google-аккаунты** появляются только при отдельном `GOOGLE_SIGNUP_ENABLED=1`. До внедрения тарификации и контроля злоупотреблений не включать массовую бесплатную регистрацию без ограничений.

### Какие действия ещё необходимы владельцу для активации Google

1. Открыть https://console.cloud.google.com/apis/credentials, создать или выбрать Google Cloud проект, настроить OAuth consent screen (название сервиса, свой домен, privacy policy).
2. Создать **OAuth Client ID → Web application**. Разрешённый веб-источник `https://ailawyer.kz`; точный Redirect URI `https://ailawyer.kz/chat/auth/google/callback`.
3. Сохранить Client ID и Client Secret ТОЛЬКО в `/etc/ai-lawyer-web.env` на VPS как `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`; права файла 0600 root, затем `systemctl restart ai-lawyer-web`. Не присылать ключ в ChatGPT и не включать в публичные коммиты.
4. Проверить тестовым Google-аккаунтом сначала привязку к существующему email-кабинету, затем отдельно политику регистрации новых пользователей. Пользователи OAuth в режиме Testing могут требовать включения в список test users.

### Какие действия ещё необходимы для открытой email-регистрации

Подключить защищённый SMTP ящик собственного домена (лучше `no-reply@ailawyer.kz`); указать `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` в `/etc/ai-lawyer-web.env`. После перезапуска сервер начнёт отправлять шестизначные подтверждения. Для публичного запуска нужны антиспам, DDoS/rate-limit по учётным записям, восстановление пароля, политика хранения и согласие с обработкой персональных данных, а также ограничение расходов API.

До настройки этих внешних реквизитов Google-вход и email-коды честно обозначаются как неактивные; **не показывать их работающими без реальной проверки**.

## Рекламные ссылки и AI-токены (пилот партнёрского привлечения)

**Важно:** AI-токены — внутренняя единица доступа сервиса. Это НЕ физические токены OpenAI API и НЕ одно и то же, что количество запросов: консультация без вложений = 1 AI-токен; консультация с файлом = минимум 3; противоречия = 6; документ = 6; стратегия/перепроверка = 8. При текущем дневном потолке можно использовать максимум 20 AI-токенов в сутки (00:00 UTC), даже если бонусный баланс больше.

- Обычная подтверждённая email-регистрация без партнёрского кода: стартовый баланс 3 AI-токена.
- Новая регистрация по **действующей рекламной ссылке** `https://ailawyer.kz/chat/?ref=КОД&utm_source=telegram`: баланс **50 AI-токенов** (эквивалент 50 коротких консультаций). Код автоматически подставляется, но поле необязательно; `utm_source` фиксируется для отчётности без передачи клиентских документов рекламщику.
- Вознаграждение начисляется сервером **только после шестизначного подтверждения email** или после верифицированного Google sign-in для НОВОЙ учётной записи (при `GOOGLE_SIGNUP_ENABLED=1`). Создание нового аккаунта по приглашению без email-подтверждения не начисляет бонус.
- Код нельзя придумать. Активные кампании создаются только root-администратором, имеют ограничения на число подтверждённых регистраций, статистику активаций и возможность отключения. Кампании не дают доступа к чужим данным.
- **Старые аккаунты:** сохраняют прежние настройки и дневной лимит; их прошлые дела не меняются. Токенный баланс в новой схеме используется только для новых подтверждённых пользователей. После внедрения оплаты потребуется миграция к общим тарифам.

Создать ссылку по SSH (после безопасного обновления сайта):

```bash
node /opt/ai-lawyer-web/web/deploy/referral-admin.mjs create 'Рекламщик Telegram' 5
```

Эта локальная команда от root создаёт/сохраняет приватный ключ администратора в `/etc/ai-lawyer-web.env` (если его ещё нет), при необходимости перезапускает только `ai-lawyer-web`, формирует индивидуальную ссылку и показывает её в терминале. Сам административный секрет в выводе отсутствует. Пятый аргумент числом — максимально допустимое количество подтверждённых регистраций, а НЕ количество AI-токенов.

Отчёт: `node /opt/ai-lawyer-web/web/deploy/referral-admin.mjs list`. Отключение: `node /opt/ai-lawyer-web/web/deploy/referral-admin.mjs disable КОД`.

Промо-пакеты — маркетинговые расходы владельца. Если резервная себестоимость 40 ₸/AI-токен, то один полностью использованный бонус 50 AI-токенов обойдётся в расчётные 2 000 ₸, а кампания на 5 подтверждённых пользователей — в 10 000 ₸ (до учёта реальных токенов, комиссии, налогов и иных издержек). Не открывать массовую регистрацию без учёта расходов API и предотвращения мультиаккаунтов.

Для обычной регистрации без приглашения ОБЯЗАТЕЛЬНО подключить почтовую отправку: создать SMTP ящик с корректными SPF/DKIM/DMARC, затем через `bash /opt/ai-lawyer-web/web/deploy/configure-auth.sh smtp` ввести параметры напрямую в защищённую SSH-консоль. Порт 465 поддерживается для SSL/TLS, порт 587 для STARTTLS. Без SMTP старая тестовая регистрация по секретному приглашению остаётся доступна, а партнёрские кредиты не активируются.

## Защита гостевого лимита от очистки cookies (17.11.2026)

- Без регистрации: **10 успешных ответов** на один гостевой сеанс; предупреждение после 5.
- Гостевой cookie обеспечивает историю и текущий остаток, но **не является единственным ограничителем**.
- Перед каждым обращением к OpenAI в зашифрованную серверную базу записывается **попытка**. Ошибки поставщика тоже учитываются в защитном бюджете: запрос мог потребить ресурсы до ошибки.
- Для учёта повторных обращений IP преобразуется в HMAC-SHA256 с приватным DATA_KEY. Исходный IP не записывается в постоянный журнал гостевых попыток. По умолчанию не более 12 попыток за 30 дней с одного IP и 40 гостевых попыток за скользящие 24 часа на весь сайт; очистка cookies и перезапуск сервера счётчики не сбрасывают.
- Настройка на VPS — `GUEST_IP_30D_MAX`, `GUEST_GLOBAL_24H_MAX` в `/etc/ai-lawyer-web.env`. Изменения требуют перезапуска `ai-lawyer-web`.
- VPN и смена IP могут обходить ограничение одного IP, поэтому действует также общий бюджет. IP одного мобильного оператора, офиса или общественного Wi-Fi могут использовать разные люди, поэтому такой контроль способен ограничить честного пользователя; он не заменяет CAPTCHA, проверку учётной записи и антибот-защиту.
- Эти лимиты ограничивают **число API-вызовов**, а НЕ реальную стоимость в долларах. Для денежного потолка нужны сбор фактического API usage, тарификация поисковых инструментов и контроль расходов проекта OpenAI.
